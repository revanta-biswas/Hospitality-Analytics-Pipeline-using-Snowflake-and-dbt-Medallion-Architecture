# Intake questions (light)

Gather the six baseline fields in one or two short batches. Prefer tappable multiple-choice with an
open "Other". Stop at six — resist going deeper. Pre-fill anything the seed context already answers.

## Outcome
- In one sentence, what business result should exist that doesn't today?
- Reflect it back stripped of solution language ("build a scanner" → "admit attendees without duplicates").

## KPI / business outcome
- Which metric should move if this works? (offer candidates: conversion, cost, time-to-X, retention, error rate, "Other")
- Rough target or direction, if known — optional.

## Rough success signal
- Directional only: "what would 'better' look like?" A number is welcome but NOT required here.
- Do not push for testable thresholds — that's refinement.

## Out-of-scope (at least one)
- What might someone assume is included that is NOT? (offer likely boundaries + "Other")
- An empty out-of-scope fails the gate — always get one.

## Known constraints
- Any hard constraints already known? (stack mandated / must integrate with X / regulatory / data rules / "none known")
- "None known" is a valid answer. Unknown ≠ assumed-absent — if genuinely unsure, it's an open question.

## Confidence + unknowns + context
- Confidence this is worth doing: low / med / high.
- Biggest open unknowns right now? (these go in Open questions, honestly)
- Link to the research / prototype / deck / notes this came from (for `context_link`).

## Then stop
Draft the baseline and run the intake gate. Do not ask about domain models, NFRs, or measurable
criteria — those are refinement's questions.
